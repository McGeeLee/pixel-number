# Pixel Number · 数字像素实验室

输入一个整数，实时浏览它对应的 RGB565 图片；拖动滑条探索附近编号，遇到喜欢的画面就保存。

源码：[McGeeLee/pixel-number](https://github.com/McGeeLee/pixel-number)。包含 Python 桌面版、命令行工具和可部署到 Cloudflare 的网页版。

## 网页版

已部署到 **https://pixels.mcgeelee.com**，支持电脑和手机浏览器，无需安装 Python。

数字转换、图片导入、PNG / JSON / TXT 导出和批量 ZIP 均在浏览器本地执行，图片和编号不会上传。网页源码及 Cloudflare 配置位于 `web/`，参见 [网页版说明](web/README.md)。网页版 JSON 与桌面版互通。

网页版默认生成 Cloudflare Pages 纯静态产物，不运行服务端 Worker。部署及自动构建设置见 [网页版说明](web/README.md)；旧 Worker 构建材料保留供回滚。

## 启动

需要 Python 3.10+、Tkinter 和项目依赖。先获取源码，再在项目目录中创建环境：

```sh
git clone https://github.com/McGeeLee/pixel-number.git
cd pixel-number
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pixel_number
```

macOS 完成安装后，也可双击 **`启动.command`**。Windows 创建并激活 `.venv` 后，使用 `python -m pip install -r requirements.txt` 安装依赖，再运行 `python -m pixel_number`。Tkinter 随部分 Python 发行版提供；可先运行 `python -m tkinter` 检查。Linux 常需安装发行版提供的 `python3-tk`。

虚拟环境不包含在仓库中，换电脑时应按上述方式重建。应用运行期间不需要联网。

## 先试这几个操作

1. 默认 **1920 × 1080**，输入 `0`，得到全黑。
2. 输入 `65535`，最后一个像素变白；右侧放大镜默认观察它。
3. 点击「下一张」，编号变成 `65536`，最后一个像素归零，倒数第二个像素变为暗蓝色。
4. 点击「随机跳转」，探索整幅随机画面；它通常看起来像彩色噪声。
5. 步长输入 `65536` 并应用，再拖动滑条。每步会跳过一个像素的全部低位状态。也支持 `2^32`、`65536^100`。
6. 点击「保存 PNG」，保存的是完整分辨率的图片。预览窗口大小不影响导出分辨率。
7. 「导入图片」选择刚保存的 PNG，可恢复相同的图像编号。

## 操作规则

- **数字输入**：支持十进制和十六进制；十六进制可带 `0x`。允许空格、换行、下划线分组。输入停止约 350 ms 后自动生成，也可按回车。
- **切换进制**：以最近成功预览的数字为准，切换其显示格式。
- **滑条**：精确浏览基点附近最多前后 1000 步。实际边界受合法编号范围限制。滑条只传递小整数偏移，编号运算始终使用任意精度整数，不经过浮点数。
- **重设基点**：输入新数字、点击前后按钮、使用黑/白/随机预设、导入图片或应用步长都会重设滑条基点。
- **步长**：修改后点击「应用步长」或按回车。前后按钮也会应用当前填写的步长。批量导出与编号保存使用已经应用的步长。
- **尺寸**：可以自定义宽高，单图上限为 16,777,216 像素。修改尺寸会重新解释同一整数，不会缩放原图；超出新尺寸容量时明确报错，不截断。
- **顺序**：高位在左上时，小数字从右下角变化；低位在左上时，小数字从左上角变化。每个模式都按行扫描。
- **放大镜**：可固定观察首/末像素，也可跟随鼠标。坐标从 `(0, 0)` 开始，显示精确 RGB 值及对应的 16 位色号。
- **保存编号**：JSON 保存完整十六进制编号、宽高、像素顺序和已应用步长，可直接重新打开。
- **导出数字 TXT**：按当前选择的进制导出完整数字。TXT 不包含尺寸、顺序等参数，重新打开时需要选择相同参数；推荐用 JSON 保存可恢复状态。
- **批量导出**：从当前编号开始，依次生成 `N + i × step`，`i = 0 … count-1`。先检查整个范围是否越界，再创建新文件夹。不会生成区间内被步长跳过的图片。

## 超大数与实时预览

1080p 的原始 RGB565 数据为 4,147,200 字节，共 33,177,600 bit；最大合法编号是 `2^33177600 - 1`，最长有 9,987,453 位十进制数字。

把千万位字符串直接放进输入框会拖慢界面，因此：

- 输入框接受至多 4096 个字符；更长的数字用「打开编号」从 TXT 或 JSON 载入。
- 大编号在输入框中显示摘要，内部保存完整整数。编辑摘要时会选中整段，便于输入新数字替换。
- 「导出数字 TXT」可取出完整数字；不会把摘要误当成原数字。
- 解析、图片转换和导出在独立进程中执行；快速拖动只保留最新待处理位置，过时结果不会覆盖新输入。
- 非法输入出现时保留上一张预览，保存按钮暂时禁用，避免把旧画面误当成新输入的结果保存。
- “实时”表示交互时持续更新预览，不保证固定帧率。大文件读取、千万位十进制转换和完整分辨率导出仍需要处理时间。

## 数学与颜色约定

设总像素数为 `P = width × height`，每个像素的 RGB565 色号为 `c[i]`，范围为 `0 … 65535`。

高位在左上的默认模式：

```text
N = Σ c[i] × 65536^(P - 1 - i)
```

低位在左上的模式：

```text
N = Σ c[i] × 65536^i
```

不足的像素位补零。合法范围为 `0 ≤ N < 65536^P`，不做循环溢出或取模。固定尺寸和顺序下，这是一一映射。

```text
r5 = (color >> 11) & 31
g6 = (color >> 5) & 63
b5 = color & 31

R8 = (r5 << 3) | (r5 >> 2)
G8 = (g6 << 2) | (g6 >> 4)
B8 = (b5 << 3) | (b5 >> 2)
```

数值 `1` 对应 `(0, 0, 8)`，是暗蓝色，不是灰色。十进制字符串的一位也不等于一个像素。

PNG 使用常见的 8 bit × 3 通道 RGB 容器，但像素只取 RGB565 的 65,536 种精确扩展色。PNG 内附带像素顺序元数据，重新导入时优先采用它。编号没有以巨大字符串重复嵌入 PNG，可直接从像素恢复。

普通照片导入时保留原始尺寸、应用 EXIF 方向，并量化为 RGB565：R/B 各保留 5 位，G 保留 6 位。透明像素先合成到黑色。这个过程可能改变原图颜色；本工具保证的是 **RGB565 量化后像素与编号的可逆性**，不保证恢复原文件字节、原始色深或透明通道。多帧图片只取当前第一帧。

## 批量文件与中断

界面会在选中的目录中新建带时间和随机后缀的批次文件夹。图片按 `000000.png`、`000001.png` 排列。`plan.json` 记录完整起点、步长和参数；`manifest.json` 记录计划张数、已完成张数与状态。巨大编号只写入一次，避免每生成一张图都重写它。

点击「停止批量」会完成当前文件后停止，保留已完成结果。关闭窗口时也会等待当前批量文件完成。每个 PNG 和编号文件均通过临时文件原子发布。强制杀进程可能留下临时文件，清单可能停留在 `running`；不要把这种情况视为完成。

## 命令行

```sh
# 只生成指定编号
.venv/bin/python -m pixel_number render --number 65535 --output white-pixel.png

# 自定义尺寸、十六进制编号
.venv/bin/python -m pixel_number render --number F80007E0001FFFFF --base 16 --width 2 --height 2 --output colors.png

# 只生成编号 10、15、20、25，输出目录必须尚不存在
.venv/bin/python -m pixel_number batch --number 10 --step 5 --count 4 --output chosen-images

# 图片 → 编号 → 图片
.venv/bin/python -m pixel_number decode colors.png --output colors.json
.venv/bin/python -m pixel_number restore colors.json --output restored.png
```

命令行不会覆盖已有输出文件。大数字可以用 `--number-file number.txt`，避免命令行长度限制。
